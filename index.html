Most retrieval projects fail the same way. "The agent offered the Smart 500 plan" and "the agent offered the Smart 5000 plan" sit almost on top of each other in embedding space. Vector search cannot reliably separate them, so the model names the wrong one with full confidence. Nothing errors — the answer is simply untrue, and nobody notices until a decision has been made on it.

Eight years across product, analytics and engineering, most recently taking an AI call-analytics product from a one-month MVP to a platform processing millions of calls, owning architecture and delivery end to end. The thread running through all of it is the same: build the evaluation before the search, and treat a result you like as the one most likely to be wrong.

Большинство поисковых проектов ломается одинаково. «Оператор предложил тариф Смарт 500» и «оператор предложил тариф Смарт 5000» лежат почти в одной точке пространства эмбеддингов. Векторный поиск не может их надёжно различить, поэтому модель уверенно называет не тот тариф. Ошибки при этом нет — ответ просто неверный, и заметят это только когда на нём уже приняли решение.

Восемь лет в продукте, аналитике и инженерии. Последнее — платформа речевой аналитики от MVP за месяц до продакшена на миллионах звонков, с полным владением архитектурой и поставкой. AI call analytics at scale Речевая аналитика на масштабе

A speech-analytics platform that turns raw client conversations into structured, queryable data: transcription, quality scoring against defined checklists, classification, and retrieval over the resulting corpus. One-month MVP to millions of calls processed.

The retrieval layer is hybrid — BGE-M3 for sparse and dense embeddings, Qdrant for vector search alongside OpenSearch for exact matching, weighted RRF fusion, then an LLM reranking pass. Around it sits the part that decides whether any of it can be trusted: a versioned prompt catalog rather than prompts edited in place, an evaluation suite, and a no-answer policy so the system abstains instead of inventing.

In front of retrieval sits an action planner: an LLM selects one of a fixed set of actions — analytics, hybrid retrieval, one of several deterministic call operations, or a clarifying question — and the system dispatches accordingly. Deterministic and numeric questions are computed from the data rather than retrieved from text. It is tool calling as a pattern, built on structured outputs rather than the tools API: when a model's output drives execution, schema conformance has to be guaranteed rather than parsed out of prose.

Backend on FastAPI with asynchronous workers (TaskIQ, RabbitMQ), PostgreSQL and ClickHouse, deployed to Kubernetes.

Платформа речевой аналитики: превращает сырые разговоры с клиентами в структурированные данные, по которым можно искать. Расшифровка, оценка качества по чек-листам, классификация, поиск по всему корпусу. От MVP за месяц до миллионов обработанных звонков.

Слой поиска гибридный — BGE-M3 для разреженных и плотных эмбеддингов, Qdrant для векторного поиска рядом с OpenSearch для точных совпадений, слияние через weighted RRF, затем LLM-реранкинг. Вокруг него то, что решает, можно ли всему этому верить: версионный каталог промптов вместо правок на месте, набор проверок качества и политика отказа — система говорит «не знаю» вместо того, чтобы выдумать.

Перед поиском стоит планировщик действий: LLM выбирает одно из фиксированного набора действий — аналитика, гибридный поиск, одна из детерминированных операций над звонками или уточняющий вопрос — и система направляет запрос дальше. Детерминированные и числовые вопросы считаются по данным, а не достаются из текста. Это tool calling как паттерн, построенный на structured outputs, а не на tools API: когда вывод модели управляет исполнением, соответствие схеме должно гарантироваться, а не вытаскиваться разбором прозы.

Бэкенд на FastAPI с асинхронными воркерами (TaskIQ, RabbitMQ), PostgreSQL и ClickHouse, деплой в Kubernetes.

Alpha Falsifier — a system built to refute its own findings Alpha Falsifier — система, которая опровергает собственные выводы

A falsification-first research pipeline for systematic trading. The point is not a strategy; it is the discipline that makes a conclusion trustworthy. Validation is built before the search, and the final test set is sealed — opened exactly once.

Исследовательский пайплайн, построенный вокруг опровержения. Ценность здесь не стратегия, а дисциплина, которая делает вывод достоверным. Валидация строится до поиска, а финальный тестовый набор запечатан и вскрывается ровно один раз.

A cross-sectional momentum strategy beat both the training and the validation set, then collapsed on the sealed one. Validation could not catch it, because validation was what I had been selecting on — repeated looks quietly turn a holdout into training data. A standard two-way split would have "discovered" this strategy and shipped a loser.

Кросс-секционная моментум-стратегия обыграла и обучающий, и валидационный набор, а на запечатанном рухнула. Валидация не могла её поймать, потому что именно по валидации я и отбирала — многократные взгляды тихо превращают отложенную выборку в обучающую. Обычное разбиение на две части «нашло» бы эту стратегию и выкатило убыток.

The search itself is agentic: an LLM proposes hypotheses with stated reasoning, a DSL compiles that structured output into executable signals, the falsifier tests them, and every verdict is written to a persistent memory that is fed back into the prompt — so the agent stops re-proposing ideas it has already had rejected.

Сам поиск агентный: LLM предлагает гипотезы с обоснованием, DSL компилирует структурированный вывод в исполняемые сигналы, фальсификатор их проверяет, и каждый вердикт пишется в постоянную память, которая подмешивается обратно в промпт — так агент перестаёт заново предлагать уже отвергнутые идеи.

Voice agent · built in two days Голосовой агент · собран за два дня

Outbound voice agent — qualification and booking Голосовой агент — квалификация и запись на встречу

Talk to the agent →Поговорить с агентом →

A live conversational agent that calls a prospect, qualifies them, offers meeting slots and books one — a two-minute call, in Russian, where latency reads as competence and any pause reads as a machine. Built on ElevenLabs Agents with a Cloudflare Worker behind it.

The decision that mattered: the model never computes a date. The worker hands it the current date, the next working days and a ready-spoken form of every slot — "on Monday the tenth of August, at eleven in the morning". The agent reads; it doesn't calculate the weekday, resolve "tomorrow", or inflect the month. That removes an entire class of errors at once, and it takes enough load off the model that a faster, cheaper one becomes viable.

One agent rather than a chain of sub-agents, deliberately: the script is short and the qualification at the end depends on what was said at the start, so every handoff would mean carrying that context explicitly — and every handoff costs hundreds of milliseconds. In voice, latency doesn't read as slowness. It reads as a robot.

The finding I didn't expect: half the work on sounding human wasn't prompting at all, it was how text lands in the synthesiser. Latin script inside a Russian phrase, abbreviations, hyphenated ranges — each turns ordinary text robotic.

Живой разговорный агент: звонит потенциальному клиенту, квалифицирует его, предлагает слоты и записывает на встречу. Двухминутный разговор на русском, где задержка читается как компетентность, а любая пауза — как машина. Собран на ElevenLabs Agents с воркером на Cloudflare позади.

Решение, которое всё определило: модель никогда не считает дату. Воркер отдаёт ей текущую дату, ближайшие рабочие дни и готовую озвучку каждого слота — «в понедельник, десятого августа, в одиннадцать утра». Агент читает; он не вычисляет день недели, не разрешает «завтра» и не склоняет месяц. Это разом убирает целый класс ошибок и снимает с модели столько нагрузки, что хватает более быстрой и дешёвой.

Один агент, а не цепочка суб-агентов — сознательно: сценарий короткий, а квалификация в конце опирается на сказанное в начале, поэтому при каждой передаче контекст пришлось бы перебрасывать явно. И каждая передача стоит сотен миллисекунд. В голосе задержка читается не как медлительность, а как робот.

Находка, которой я не ждала: половина работы над живостью оказалась вообще не про промпт, а про то, как текст ложится в синтезатор. Латиница внутри русской фразы, аббревиатуры, диапазоны через дефис — каждое превращает нормальный текст в роботизированный.

Delivered with an explicit list of what was left undone — synthetic slots, no CRM webhook, empty holiday calendar — and the order I would build them in. Сдано с явным списком того, что не успела — синтетические слоты, нет вебхука в CRM, пустой календарь праздников — и порядком, в котором я бы это делала.

Speech to structure · open source Речь в структуру · открытый код

Meeting Intelligence — audio in, protocol out Meeting Intelligence — аудио на входе, протокол на выходе

Drop in a recording and get back a structured protocol: summary, decisions, action items and the topics actually discussed, with PDF export and a searchable history. Audio through an ASR endpoint, transcript through an LLM, out as structured fields rather than prose — so the result can be filtered and searched, not just read.

Built for Kazakh and Russian mixed speech, which is where general-purpose transcription tools do worst. Code-switching mid-sentence is normal here and most ASR models are trained as though it isn't — the same problem I measured properly at work, benchmarking engines against hand-annotated golden datasets across six language pairs rather than trusting vendor claims.

The recognition engine is selected per language rather than left to auto-detection. Everything downstream is only as good as that first step: a misheard figure or name propagates into the protocol as a fact, and nothing after it will question it.

Загружаешь запись и получаешь структурированный протокол: резюме, решения, поручения и темы, которые действительно обсуждались, плюс экспорт в PDF и история с поиском. Аудио через ASR, расшифровка через LLM, на выходе структурированные поля, а не проза — так результат можно фильтровать и искать, а не только читать.

Сделан под смешанную казахско-русскую речь — там, где универсальные инструменты расшифровки работают хуже всего. Переключение языка посреди фразы здесь норма, а большинство ASR-моделей обучены так, будто её нет. Ту же задачу я мерила по-настоящему на работе: сравнивала движки на размеченных вручную эталонных наборах в шести языковых парах, а не верила обещаниям вендоров.

Движок распознавания выбирается под язык, а не отдаётся автоопределению. Всё, что дальше, не лучше этого первого шага: неверно услышанное число или имя уходит в протокол уже как факт, и ничто после не поставит его под сомнение.

Question answering over research papers Ответы на вопросы по научным статьям

Upload PDFs, index them into a local Chroma vector store, ask questions and get answers with citations back to the source paper. Built on LangChain — document loaders, splitters, and a RetrievalQA chain — with OpenAI embeddings and a Streamlit interface.

A compact reference implementation of the pattern most clients ask for first, and a useful baseline for showing where plain dense retrieval starts to break.

Загружаешь PDF, они индексируются в локальное векторное хранилище Chroma, задаёшь вопрос и получаешь ответ со ссылками на исходную статью. Построено на LangChain — загрузчики документов, сплиттеры, цепочка RetrievalQA — с эмбеддингами OpenAI и интерфейсом на Streamlit.

Компактная эталонная реализация того, что клиенты просят первым делом, и удобная база для демонстрации, где чистый плотный поиск начинает ломаться.

Four decisions that separate a demo from a system Четыре решения, отличающие демо от системы

Hybrid retrievalГибридный поиск

Sparse and dense embeddings together, vector search alongside keyword search, fused with weighted RRF and reranked. Exact terms, product codes and figures stop disappearing from results.

Разреженные и плотные эмбеддинги вместе, векторный поиск рядом с ключевым, слияние через weighted RRF и реранкинг. Точные термины, коды продуктов и цифры перестают исчезать из выдачи.

Evaluation before shippingОценка до релиза

A golden question set with known answers, measured on every change. Without one, "it seems better now" is your only quality signal — and it is usually wrong.

Эталонный набор вопросов с известными ответами, прогон на каждое изменение. Без него «вроде стало лучше» — единственный сигнал качества, и обычно он врёт.

Abstention over inventionОтказ вместо выдумки

Below a confidence threshold the system says it does not know. Every answer carries citations, and computed answers surface the query so they can be checked.

Ниже порога уверенности система говорит «не знаю». Каждый ответ несёт ссылки на источник, а вычисленные ответы показывают сам запрос, чтобы их можно было проверить.

Permissions at retrieval timeПрава на этапе поиска

Access rules applied when documents are selected, never in the prompt. Once a document is inside the context window, no instruction reliably keeps the model away from it.

Права доступа применяются при отборе документов, а не в промпте. Как только документ попал в контекстное окно, никакая инструкция надёжно не удержит модель от его использования.
